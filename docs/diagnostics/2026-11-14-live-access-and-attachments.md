# Доступы во время хода, положение ленты и вложения

Версия исправления: 0.0.70.

## Причины и изменения

Ранее SecretStorage читался один раз перед запуском провайдера. Сохранение
новой карточки или переменной меняло настройки, но уже запущенный CLI получал
только исходное окружение. Теперь каждый активный ход имеет отдельный канал
полных снимков, привязанный к логическому проекту и контроллеру запуска.
Сохранение и первоначальное чтение сериализованы; публикация следует после
успешной записи в SecretStorage. Несколько профилей одной папки не смешивают
доступы. Ошибка доставки показывается отдельно от результата сохранения.

Новые Bash/Zsh-команды читают последнюю опубликованную версию. Снимок хранится
в приватной временной папке в зашифрованном виде: AES-256-GCM, отдельный случайный
ключ хода в окружении, новый nonce каждой публикации, проверка аутентичности
до вывода расшифрованного содержимого, атомарная замена файла. На POSIX
проверяются владелец, тип, права, число ссылок и ограниченный размер файла;
чтение не следует за символической ссылкой. Значения не попадают в команды,
публичный manifest, чат или глобальную конфигурацию CLI. На время применения
снимка shell tracing выключается. После остановки собственных процессов
временная папка удаляется.

В Codex снимок shell отключается только для запуска данного процесса, чтобы
он не возвращал устаревшее окружение. В Claude SDK добавлен Bash PreToolUse
с префиксом загрузки актуального снимка, без разрешающего permissionDecision.
Остальные hooks и проверки разрешений сохраняются. Составная команда может
потребовать подтверждения там, где раньше срабатывал простой Bash allowlist.

Уже выполняющаяся команда, длительно работающий процесс и отдельный MCP-сервер
не получают изменения своего окружения задним числом. Для Codex на Windows
с PowerShell сохранён исходный снимок и выводится сообщение об ограничении;
автоматическое обновление PowerShell в эту версию не входит.

Настройки и архив заменяют DOM ленты чата. Позиция теперь сохраняется при её
отсоединении и восстанавливается после возврата и поздних изменений высоты.
Ключ включает плитку, логический проект и сессию. Новые сообщения сохраняют
место чтения; следование за последним сообщением продолжается только при
соответствующем положении ленты и включённой автопрокрутке.

Новая кнопка «Текст» сохраняет введённый текст как UTF-8 `.txt` через существующий
канал вложений. Ошибка оставляет текст для повтора. Просмотр изображения
использует штатный редактор VS Code. Замена ждёт успешного сохранения нового
файла; прежний файл из истории не удаляется. Ответы загрузки привязаны к
черновику, проекту, сессии и ID загрузки; отправка блокируется до её окончания.

## Проверка на настоящем Codex

Установленный CLI 0.167.2 запущен с изолированным CODEX_HOME и локальным
тестовым Responses-сервером, без реальных API-запросов и пользовательских
доступов. Сервер выдавал штатный native `exec_command` через function_call.
В каждом случае использовались один процесс, один thread и один активный turn.

| Права | Первый вызов | Второй вызов после обновления | Третий после удаления |
| --- | --- | --- | --- |
| workspace-write | Исходные значения | Замена, добавление и удаление видны | Снимок пуст |
| danger-full-access | Исходные значения | Замена, добавление и удаление видны | Снимок пуст |

Все шесть команд завершились с кодом 0. Процессы и локальные порты тестов
закрыты, временные папки удалены. Первоначальный вариант через Unix socket
был отклонён после реального EPERM в обычной песочнице. Права не расширялись;
в итоговом коде socket-транспорт отсутствует.

Тесты охватывают гонку сохранения при запуске, независимость профилей/плиток,
поворот и удаление переменных, специальные символы, отсутствие открытых
значений на диске и в tracing, повреждение/подмену снимка, очередь публикаций,
отмену и завершение процессов до удаления bootstrap-файлов, прежнее
восстановление ready-fork, ошибки загрузки и запоздалые ответы вложений.
Числовое покрытие строк не измерялось.

## Результаты выпуска

- Node 22.23.2, `npm run typecheck`: успешно.
- `npm test`: 844 проверки, 843 пройдены, одна существующая пропущена,
  ошибок нет. POSIX-проверки shell не выдаются за поддержку PowerShell.
- `npm run build` и упаковка VSIX для darwin-arm64: успешно.
- В реальном Chrome: 21 сценарий вложений и навигации пройден, ошибок
  консоли и неудачных сетевых запросов нет. Сверены 150 003 символа /
  290 003 байта UTF-8 после ошибки сохранения и повтора. Проверены обычный
  и редактируемый запрос, независимость двух плиток, скрытие доски архивом.
- Окно текста проверено на ширинах 1440, 768 и 375 px, включая `Esc`,
  возврат фокуса и axe. Без эталонных скриншотов визуальное сравнение
  остаётся неопределённым; измерения синтетического host не являются
  показателями производительности настоящего VS Code.
- Дополнительные регрессии воспроизводят прерывание плавного перехода
  новым сообщением и запоздалое программное событие scroll после layout.
  Переход к последнему сообщению теперь мгновенный; неизменившаяся
  программная позиция не отменяет намерение следовать за ответом.

После уточнения валидации имён повторена проверка обеих песочниц на итоговом

по три native-команды прошли в каждом режиме. Аудит всех десяти текущих
и предыдущих тестовых запусков не нашёл оставшихся собственных процессов
или открытых портов.
